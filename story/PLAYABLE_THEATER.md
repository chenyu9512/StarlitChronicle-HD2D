# 剧情交互演出模式（开发测试）

在Godot 4.7.2中打开 `res://scenes/story_theater.tscn`，按 **F6** 运行当前场景。

与只读预览不同，该演出场景真正实例化 `StoryRuntime`：
- 逐句显示序章和全部72章的文本，支持跨章进入条件。
- 逐个完成带稳定target ID的任务目标；输入结果写入故事旗标。
- 展示章节对话选项并立即写入选择状态。
- 遇到有Boss的场景，显示“模拟胜利 / 模拟失败”调试按钮；**这里不是真实战斗**，仅测试分支和锁定是否正确。
- 每次对白翻页与章节结算会保存到 `user://starlit_story_v1.json`（剧情独立存档，版本2）。旧版游戏存档 `user://starlit_save_v1.json` 不会被覆盖。
- 第60、66和71章结算时，运行器会同步结局所需世界旗标；收集12张航页仍需通过支线三个阶段，不能直接跳过条件。

**注意**：本演出模式未接入实际地图触发、角色立绘、NPC行走、装备掉落或战斗动画。它是编剧测试工具，正式游戏场景仍需接线。现有主游戏 `scenes/main.tscn` 保持不变。

**调试重开：** 在Godot编辑器用户数据文件夹中删除 `starlit_story_v1.json`。删除该文件会清除剧情演出模式进度，**不会**清除原型的 `starlit_save_v1.json`。

**场景触发接线**：正式地图完成玩家互动后调用 `complete_objective(target)`。当 `battle_requested` 发出时实例化战斗器，在实际胜利/失败后调用 `report_battle_result(bool)`。正式结局选择的选项受 `requires_flags` 约束。

**未实测说明**：只有源码接口层和静态检查；仍须在 Windows Godot 4.7.2 用F6实际启动以确认字体、节点与按钮行为。
