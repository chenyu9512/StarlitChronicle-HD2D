# 星灯纪行｜地图 V3 独立关卡制作系统

## 当前真实交付

地图V3已经进入 Godot 场景加载层，**不是独立于游戏的策划案**。

- `data/levels/v3/`：40个独立 `map_*.json` 关卡文件，每个保存属于自己的72×48地块、道路折线、水道、山体障碍、清理空地、碰撞覆盖和地砖手工修正。两个旧版原型不作为正式关卡。
- `data/levels/world_levels_v3.json`：40区源数据合集，是无独立文件时的只读后备。正常运行**优先读取独立JSON文件**，不应同时编辑同一关卡的两份数据。
- `scripts/world_level_v3.gd`：读取、绘制V3图层并验证尺寸与ID；支持手工覆盖地形和障碍、按编辑值覆盖现有地图。地表绘制与角色实际碰撞共享相同数据。
- `scripts/world_geography.gd`：V3野外采用独立道路网，任务点从最近的作者指定道路节点连接，避免旧版“所有线路都从主角出生点辐射”的单一布局；城镇和地下城保留既有6种街道、8种房间设计，同时接受独立文件里的精确地砖/碰撞修正。
- `scripts/world_fog_v3.gd`：玩家移动探索后的迷雾，单张72×48地图仅432字节未编码位图数据，压缩为base64保存在 `rpg.world.fog`。每个室内与室外分开保存探索状态；载入旧存档不重建或覆盖其他数据。
- `scripts/map_view.gd` 与 `map_hud.gd`：小地图/地区图读取真实地形、水路、阻挡和探索迷雾，显示当前探索完成度。
- `tools/smoke_world_v3.gd`、`smoke_world_fog_v3.gd`：测试独立地形加载、碰撞编辑、地图唯一性、道路/主线任务/地区出入口可达性、雾图存档与室内区分。

## Windows 可视化编辑器

在仓库根目录运行：

```powershell
python tools/map_v3_editor.py
```

不依赖ComfyUI、联网服务或付费API；使用Python标准库Tkinter。

操作：
1. 顶部选择任意一张地图（`map_coast_03`等）。
2. 选择 road / trail 连续点击道路节点，双击完成折线。
3. obstacle / water 绘制地貌障碍或水道；clearing 创建空地。
4. floor / wall 在指定格精修地砖并调整碰撞；右键删除当前格的手工标记。
5. 点击 **保存全部地图**，编辑器将每个地区存入自己的 `data/levels/v3/<map_id>.json`，游戏启动时直接使用这些文件。
6. 可按地区导入和导出单张关卡JSON，与其他美术/关卡编辑人员交接。
7. 检查文件：
```powershell
python tools/map_v3_editor.py --check
python tools/materialize_world_v3.py --verify
```

修改后必须运行 Godot 的地图专项回归，再提交 `main`。若把任意NPC、出口、Boss房路径封死，`smoke_world_v3.gd` 或 `smoke_world_production.gd` 应阻止验收。

## 图层与关卡生产优先级

1. **野外（首批已接入并专项通过）**：各地图自己的道路网、河渠、山脊、地表阻挡、景观、局部任务接入，并渲染水面和探索迷雾。
2. **城镇**：原有11座城镇、6种街道和建筑系统保留；V3逐格美术及碰撞覆盖已接入，后续仍需每座城镇的人工布局、美术/家具与居民生活场景终稿。
3. **地下城**：原有8种房间网络和双符文/宝箱逻辑保留；V3逐格美术与阻挡修正已接入，后续仍须完成每座地牢不同的机关、Boss房与镜头演出。
4. **地图UI**：三级地图、最短可解锁路径、V3探索迷雾与进度已接入，设备安全区、触控手势和动画仍待现场测试。
5. **战斗演出**：本批没有将原有玩法的静态指令冒充商业演出；原战斗系统保持完整且纳入全工程回归。
6. **实玩验收**：已有 Godot headless 静态/剧情/地图回归与Windows/Linux预览导出；尚未完成真实设备72章人工通关、性能与美术商业验收。

## 验收原则

`CI=Success` 代表自动化场景、数据和脚本经当前测试覆盖的范围通过。它**不等于**40张地图逐格美术精修完成，也不等于达到《勇者斗恶龙》商业发行级制作质量。当前仍需要专属美术、音乐、剧情实玩与PC/iPhone QA。
