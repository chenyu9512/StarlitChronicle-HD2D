# 《星灯纪行》指定美术优化分支开发与批次验收政策（2026-10-27）

> 2026-10-27 用户最新指令覆盖此前“main-only”政策：从此以 `Main2美术优化版` 为**唯一日常开发目标**。仓库 GitHub 默认分支若仍显示 `main`，只代表网站默认入口，不能视为开发提交目标。
>
> 执行计划以 [开发总控](DEVELOPMENT_MASTER_PLAN.md) 为准；工作流清单见 [工作流清理记录](WORKFLOW_CLEANUP_2026_10_27.md)。既有 `main` 和当前美化资源迁移提交均应完整保留。

## 用户确认的最新原则

1. **A/B/C/D及后续新增代码、地图、美术素材、测试、文档及Bug修复，全部明确提交到现有 `Main2美术优化版` 分支。** 每次GitHub文件写入须显式指定 `branch=Main2美术优化版`，不得省略分支参数而意外写到GitHub默认 `main`。
2. 保留 `main` 为原有基线，不将美化分支批量覆盖到 `main`；不自动合并、强推、重置、创建新开发分支或PR。任何跨分支迁移都应取得用户单独决定。
3. 小幅修复可以连续提交，但不在每次提交后执行昂贵的完整 Actions/Godot；在明确批次和SHA后执行一次冻结版正式回归。此前 `main` 的测试成功不得冒称为美化分支最新SHA验收。
4. 保留现行12项CI入口；当工作流含 `push.branches` 过滤时，只对 `Main2美术优化版` 的专用 `docs/qa-*.json` 触发。无需等到设置仓库默认分支改变才开始在此分支开发。
5. 测试、资源审计及CI绝不自动删除分支、关PR、强推或删除仍可能被运行时引用的素材。所有原档、候选、运行时素材迁移按依赖关系和测试证据处理。
6. 共享主控与资产路径修改遵循最新文件SHA逐项更新；保留原有美化分支的资源选择和第三方素材迁移结果，禁止从 `main` 整文件覆盖而冲掉更新。

## 验收原则

- **DESIGN**：数据存在；**WIRED**：实际入口已接通；**GODOT_VERIFIED**：目标分支指定SHA已跑成功；**PLAYER_ACCEPTED**：正常玩家六章连续通关和画面验收；**RELEASE_ACCEPTED**：各平台和资源许可发行门禁全部通过。
- 不能用 `main` 的历史绿色日志证明 `Main2美术优化版` 的构建成功。资源文件结构变动尤其需验证Godot导入、实际渲染和失效引用。
- 批次失败不回写 `main`；修复和回归仍在 `Main2美术优化版`，冻结SHA后更新对应QA日志。
