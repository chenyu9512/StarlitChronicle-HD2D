## 01｜游戏概览

`星灯纪行`希望呈现一部兼具长篇群像叙事、探索感与养成深度的传统 JRPG：走出村镇、穿过大陆与群岛，认识各地居民，逐步揭开过去的故事；战斗之外，选择与行动也会改变人们的命运。

**游戏的设计支柱**

- **贯穿全篇的冒险叙事**：序章、12幕72章主线、重要同伴线及A/B/C三种结局；故事以「七灯」「记录与遗忘」「十二年后的世界」为核心主题。
- **可实际探索的世界**：8大地理区域、城镇与野外节点、地下城、建筑室内、昼夜与天气，以及迷雾逐步揭露的大小地图。
- **有策略的指令式战斗**：四人编队、职业与装备组合、敌我速度时间轴、元素弱点、异常状态和原创「聚星」蓄力。
- **不只为数值而存在的支线**：居民、地区与伙伴任务围绕社会关系、责任和长期影响设计，选择后果通过后续章节与回访展开。
- **旅行之外的日常**：购物、锻造、客栈、公会、营地、住宅、家具与烹饪，形成冒险中的补给和生活循环。

**制作参考与原创性**：本作参考经典《勇者斗恶龙》等日式 RPG 在探索节奏、职业成长、回合策略和用户体验方面的通用设计理念；故事、角色、地名、玩法名称与自有美术资产均按原创项目制作，不宣称获得相关系列授权，也不直接使用其受版权保护的角色、音乐、地图或素材。

## 03｜世界与故事

游戏发生在**洛维恩**：由八大区域、七座母灯与多种历史记忆交织的世界。故事从童年星灯祭展开，逐步触及「黑星之夜」、记录消失、不同地区的生存方式，以及十二年之后人们如何继续生活。

**八大冒险区域**：白砂海岸、三誓诸国、赤炉联邦、海歌群岛、镜眠王国、失落旧洲、天轨圣域、群灯之城。每个地区对应独立的地理气质、历史冲突、居民生活和主线推进节点。

**三结局**不是单纯更换一句终章对白；其核心意图是展示不同世界规则下「谁拥有决定权、谁承担代价」。结局 C 需要满足失落航页、分散灯网与七灯修复等条件。关于剧情事实、分支先后与稳定事件 ID，应以[正典主线 JSON](story/campaign/)及[当前阅读索引](story/SCREENPLAY_CURRENT_INDEX.md)为准。

为了避免剧透，仓库首页不展开第72章最终选择；完整分场、角色背景、任务文本和编剧审计可以从[剧情总目录](story/README.md)进入。

## 04｜核心玩法

### 世界探索与地图

- **区域探索**：可到达的野外、城镇与地下城；道路邻接、剧情解锁、出生点和任务位置遵循统一数据。
- **四级地图体验**：HUD 小地图 → 当前区域地图 → 地区地图 → 世界航路；支持玩家、出口、NPC、商店、宝箱和任务目标标记。
- **可存档的探索迷雾**：移动后逐步揭示道路，室内和室外有独立探索记录。
- **城镇与日常**：居民互动、商店、客栈、公会、锻造、住宅与日夜/地区天气。
- **地下城**：房间网络、通路限制、符文机关和一次性宝箱奖励；专属高级解谜仍属制作计划。

地图实际实现为**可单独编辑的区域数据 + Godot运行时TileMapLayer绘制/碰撞**，而不是已经交付40套不同美术导演的独立`.tscn`关卡。

### 战斗与角色养成

- 四人战斗编队与职业技能主动选择，攻击、防御、治疗及目标选择。
- 依速度形成**敌我混合回合序列**，配合敌人行动与异常状态处理。
- 元素弱点、护盾、能力强化、异常抗性与 Boss 控制免疫。
- 七类异常状态：中毒、灼烧、眩晕、睡眠、冻结、沉默、迟缓。
- 原创「聚星」分层蓄力，以及休闲、标准、挑战三种难度。
- 基础/高级/终阶职业、独立职业熟练度、装备、素材与锻造循环。

目前上述属于**可运行系统基础**。尚需逐 Boss 的独立机制、战斗动画和镜头、清晰的行动顺序呈现、不同职业流派平衡及全篇难度曲线验收。

### 任务、同伴与家园

- 原基础任务体系保持120条总量；玩家可追踪任务、获得奖励并推进进度。
- 后续章节中的社会回应、同伴态度和长期影响已在剧情文本层逐步展开；**后续A/B事件接入游戏地图**是下一批内容工程。
- 住宅可购买、升级、布置家具、储存素材、休息和烹饪；当前采用可操作的功能型室内界面，后续需升级为完整独立室内关卡表现。

## 05｜下载与启动

### 方式 A：下载 Windows / Linux 开发预览

1. 进入 [GitHub Actions — Desktop Playable Preview](https://github.com/chenyu9512/StarlitChronicle-HD2D/actions/workflows/desktop-preview.yml)。
2. 选择一个**成功**的运行记录，展开页面底部的 **Artifacts**。
3. Windows 下载 `StarlitChronicle-Windows-x64-preview`；Linux 下载 `StarlitChronicle-Linux-x64-preview`。
4. 解压完整文件后运行相应可执行文件。

预览包由工作流自动生成，**不代表已正式发售**。Artifacts 默认保留14天，过期后可在有权限的情况下手动触发工作流重新构建。该项目当前为私有仓库，访问下载和源代码需要对应GitHub权限；Windows预览未签名，系统可能出现安全信誉提示。

### 方式 B：从源代码运行（推荐开发者）

**环境**：Windows / Linux + Godot **4.7.2**；Git；如需执行内容校验或地图编辑器，建议 Python 3.12。

```powershell
git clone -b main https://github.com/chenyu9512/StarlitChronicle-HD2D.git
cd StarlitChronicle-HD2D
```

在 Godot 项目管理器选择 **Import / 导入**，打开仓库根目录的 `project.godot`，完成资源扫描后按 **F5**。正式主场景为 `scenes/first_act.tscn`，旧版 `scenes/main.tscn` 仅用于历史对照。

| 操作 | PC 默认输入 |
| --- | --- |
| 移动 | WASD / 方向键 |
| 调查 / 对话 | E；项目亦配置 Z / 空格为交互键 |
| 菜单 | M / Esc |
| 地图 | 游戏内小地图和地图界面（部分地图视图支持 Tab / P） |
| 移动端 | 已有触屏控制接线；实际 iPhone 操作体验仍需真机确认 |

**存档**：开发版使用本地 `user://first_act_v3.json` 自动存档，并支持三个手动槽位和备份恢复；旧档兼容是工程测试项，但重大更新前仍建议备份 Godot `user://` 中的存档。暂无已发布的跨设备云存档服务。

### 方式 C：地图 V3 编辑

```powershell
python tools/map_v3_editor.py
python tools/map_v3_editor.py --check
python tools/materialize_world_v3.py --verify
```

编辑器使用 Python 标准库 Tkinter，可编辑道路折线、水域、障碍、空地、地砖覆盖和碰撞。正式地图的权威制作入口为 `data/levels/v3/map_*.json`；`data/levels/world_levels_v3.json` 是汇总/后备数据，不建议双端重复修改造成冲突。**每次调整必须验证任务点、出口、NPC及Boss路径可达。** 详见[地图 V3 指南](docs/MAP_V3_AUTHORING.md)。

## 06｜商业级交付路线

> 目标是逐步从「系统覆盖完整的可玩工程」推进到「场景、叙事、战斗、音画与平台质量均可验收的商业游戏」。阶段通过以可重复的测试、完整玩家实玩与资产审查为准，不以文件数量替代质量。

| 优先级 / 阶段 | 下一项生产目标 | 商业级验收门槛 |
| --- | --- | --- |
| **P0 · 基线与连续集成** | 保持核心脚本、ID引用、存档迁移、剧情锁与地图验证稳定 | 最新主线提交CI成功；关键失败有日志与回归用例；不强推覆盖代码 |
| **P1 · 地图 V3 正式关卡** | 先野外，再11城镇/建筑、8类地下城，逐图精修地貌和任务线路 | 地图布局非重复模板；全部关键交互可达；谜题、战斗与返程可完整玩通 |
| **P1 · 剧情运行时联调** | 把第17—18阶段的分支候选绑定NPC、坐标、事件窗口、存档与回访 | 120基础任务及A/B长期结果逐项测试；旧档缺少分支旗标时不得擅自代选 |
| **P1 · 战斗与经济成品化** | 逐Boss机制、职业定位、装备特性、掉落、AI与成长曲线 | 主要流派可行；三难度全篇不出现关键软锁或异常奖励 |
| **P1 · 全套音画与UI** | 人物/怪物动作、独立城市和地下城画面、场景光效、BGM/SFX、UI皮肤 | 统一美术风格、合法授权台账、清晰触控/手柄反馈、演出审美评审通过 |
| **P2 · 全剧本实玩** | 序章到72章、三结局、任务后续与大量存档恢复 | 全量人工通关与剧情分支回放；无P0/P1阻塞；文本/事实/时序一致 |
| **Release Gate · 桌面与iPhone** | 正式构建、签名、帧率/内存/功耗、无障碍、兼容性和商店资料 | 真机/桌面目标机型通过；发行检查表和授权记录齐全，再宣布可售 |

**当前最重要的制作缺口**不是再堆章节或素材数量，而是将已有40区地图与庞大的剧情候选资源转化为每章真正不同、可探索、可演出、可连续通关的玩家体验。
