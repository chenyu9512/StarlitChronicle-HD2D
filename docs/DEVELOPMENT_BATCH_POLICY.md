# 单一 main 分支开发与批次验收政策（2026-10-27 当前版）

> 当前执行任务以 [开发总控](DEVELOPMENT_MASTER_PLAN.md) 为准；工作流清单见 [工作流清理记录](WORKFLOW_CLEANUP_2026_10_27.md)。以下历史合并记录仅供追溯。

## 用户确认的最终原则

1. **以后所有新开发直接提交到 `main`，不再创建新开发分支或新的功能 PR。**
2. 小幅修复、资源和剧情更新可以连续提交，但**不在每次提交后运行完整 GitHub Actions / Godot 测试**。
3. 当一个完整的功能范围成熟时，只运行**一次**完整批次验收：更新 `docs/qa-batch-trigger.json` 中的批次名称，或在 GitHub Actions 手动执行 Godot Core Validation。
4. 保留12项专项、核心及全量测试按需手动触发；部分仅监听 docs/qa-*.json 批次标记。禁止测试流程自动提交素材/地图或更改分支与PR。
5. **不再自动删除历史分支、不自动关闭 PR。** 2026-10-27 已从 Godot Core Validation 删除相关清理 job。清理属于人工独立的仓库管理操作，不能绑定测试成功回调。
6. **主分支没有额外的预合并 QA 门槛**，这是用户明确选择的“先合并，再批次验收”模式。为减轻风险，必须保留完整 Git 历史、原始提交 SHA、存档兼容回归和验收记录，禁止覆盖已经较新的正式内容。
