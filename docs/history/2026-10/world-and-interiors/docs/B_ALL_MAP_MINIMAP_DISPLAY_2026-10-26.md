# B线 · 全40地图与小地图统一显示（2026-10-26）

## 目标与边界

本批修改 **运行中的主游戏地图界面**，不只是设计稿：`scripts/map_hud.gd` 和 `scripts/map_view.gd` 是 `scripts/first_act.gd` 预加载的正式 UI。遵循仅 `main` 开发、不建分支/PR、不更改正典地图、NPC、任务及剧情ID的约定。

**美术成熟度与运行验收不能混淆**：地图的可视化/导航功能此次更新；原有40张地图的 `art_status=not_final_painted` 没有被冒充为商业最终手绘地图，也没有改写战斗、世界传送权限、碰撞或奖励存档。最终Godot运行和逐图视觉签收必须有日志/截图才能称为通过。

## 实际变更

- 共享的本地地图渲染器从 `world.terrain_layout.size` 取真值，兼容82–102列、52–72行的40张扩展地形及72×48室内，而不是把全部地图强行当作72×48显示。
- 小地图跟随玩家，按当前横屏可用像素选取可读的格子窗口（最多25×17，较小屏幕缩小窗口）；队伍位置使用实地坐标，玩家标记显示朝向。
- 全屏区域地图初始显示整张地图，提供1–4倍缩放、滚轮/触摸板缩放、触屏/鼠标拖动和一键定位；首次打开或地图/室内切换时复位，防止上一张地图的平移值污染新场景。
- 海岸、高地、火山、群岛、雾林、荒地、天穹、王都八个地区及室内拥有可辨别的UI配色；水、道路、障碍、可通过地面颜色规则统一，绝不修改真实地形/碰撞。
- 玩家主线、支线、商店、NPC、探索点、机关、出入口等只根据当前 `world.nodes` 和 `fog.revealed` 描绘；未探索的非任务目标不偷跑，屏幕外任务在小地图边界做对应的金/蓝方向提示。
- 世界航路绘制既有40个正式 `playable` 点，不把两个原型地图当成可旅行目标。地点点按采用最近点选择，仍只能通过 `WorldRegistry.can_travel` 和 `shortest_route` 按故事解锁的合法相邻线路前往；地图浏览不新增发现标志。
- 小地图标题指示当前地区，全屏图显示场景状态、探索百分比、坐标与授权路线；原误导性的 `已到访/42` 修正为40张正式地图。
- 地图或室内切换自动匹配当前 `fog_key()`，使用原有持久化迷雾，不重置旧档探索或为玩家预揭示未知地形。

## 新增验证与门禁

新建：
- `tools/validate_all_map_display.py`：静态核对正典、V3独立文件、尺寸、区位、邻接与97室内身份和出生点。
- `tools/smoke_all_maps_minimap.gd`：在真实 Godot 场景下循环构建全部40张 TileMapLayer，检查实体网格、地图/小地图视域、缩放、客栈进出后室内外尺寸和40世界点与权限。
- `.github/workflows/map-ui-validation.yml`：将上述验证接入现有 **手动批次** map UI 验收（不是每个小提交自动运行）。

源码静态跨表抽检（当前会话经GitHub工具实际核对）得到40/40地图的正典尺寸、世界区位与邻接一致、40份V3文件存在，40份独立布局与聚合目录匹配。此证据属于 **SOURCE_VERIFIED**，非Godot通过；新增Python脚本也要在完整仓库运行才可认定PASS。

建议在最终集成SHA执行：

```sh
python3 tools/validate_all_map_display.py
python3 tools/materialize_world_v3.py --verify
godot --headless --path . --editor --quit
godot --headless --path . --script res://tools/smoke_map_ui.gd
godot --headless --path . --script res://tools/smoke_all_maps_minimap.gd
godot --headless --path . --script res://tools/smoke_world_fog_v3.gd
godot --headless --path . --script res://tools/smoke_world_production.gd
```

最后由D线验证：游戏开始→大地图→地区→当前区域→缩放/拖动→离开地图→进入建筑→小地图换室内→出门→前往合法邻图→退出存档→读档后迷雾、坐标与目标正确。C线需另交地图真实最终美术与版权验收。不能用模拟旗标、瞬移或图鉴假进度代替玩家实测。
