## 一、不可变的产品决策

- **原创、离线单人、剧情驱动的指令回合制JRPG**；以成熟经典JRPG的完成度为目标，不转向MMO、不复制其他作品内容。
- 世界规划：8地区、40张正式地图；主线序章＋12幕72章；66场剧情Boss；20职业；120条基础支线/地区/伙伴任务。数量代表内容目录和开发范围，**不代表已完成商业级实装**。
- **不启用探索迷雾**；地图信息展示与实际道路解锁分开，禁止以假传送取代玩家真实步行。
- **第一幕六章先成品后扩量**：新游戏→探索→NPC→房屋进出→线索→Boss→奖励与补给→保存/重载→下一章，连贯走通后再推广到其余地区。
- 美术只使用最终确认的正式素材映射；制作原档、候选、正式运行资源分层管理。C线美术分配仍在进行，**不得为了仓库清理删除未验明引用的资产**。
- **main-only**；不建开发分支、PR，不强推。A/B/C/D分工开发，共享控制器由D线统一接入并使用读取最新版本后的逐文件安全提交。

## 五、逐批执行与退出门槛

### M0.1a：地图可信度恢复（当前首要）
1. 对晨露村、白砂港的所有可进入建筑建立“美术门口→阻挡图→脚点→交互→室内出口→安全返程”逐门对照。
2. 替换仅作通用提示的路牌；确认真实标牌具有方向、地点或告示内容。
3. 道路出口统一显式配置：source_map、destination_map、exit_cell、arrival_cell、facing、chapter_gate；静态检测必须双向一致，正式交互仍按剧情解锁。
4. 以第一幕为样板检查碰撞与可视边界；静态BFS和实际移动、手柄/键盘、存档回程均需覆盖。

### M0.1b：存档与奖励可靠性
- 对新档、旧档、房内保存、路口保存、Boss战败/胜利与重复回调进行故障注入；保存失败不得奖励重复到账或角色卡在房间/墙内。
- A/B提交数据与测试，D统一接到正式第一幕控制器并签收。

### Batch 1：统一交互层
- 玩家面对目标、接近距离、无遮挡/可达、交互键、反馈、输入锁、过场/战斗返还都走同一合同。
- 地图NPC、家屋、任务、服务、门和地区出口不得互相抢焦点。

### Batch 2：第一幕六章黄金样板
- **晨露村→白砂港→盐风古道→潮蚀海洞→鲸骨浅滩→潮歌灯塔** 按正典实际目的地与真实道路布局验收；第4章黑帆酒馆和第2章收容所是必要室内场景。
- 完整追踪六章Boss、任务选择、NPC、手感、昼夜音画、玩家正常移动、存/读档。
- 全过程不跳章、不作弊；录屏或截图证据附所测SHA。验收前不能向其余地图简单大批复制。

### Batch 3/4：扩大内容并面向发行
- 按地区分批把黄金样板契约应用于40图/72章/66Boss/120任务/20职业，每批记录入口、玩家动作、结果、存档字段、资源与测试。
- 发行阶段做资产许可、Windows/Linux预览、后续移动设备与性能测试，均需独立签核。
