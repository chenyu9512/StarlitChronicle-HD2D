## 0. 一页结论

《星灯纪行》是一款**原创、单人离线、长篇剧情驱动的经典 JRPG**，以洛维恩大陆及群岛的七座母灯、黑星之夜的历史、居民日常与玩家抉择为故事核心。参考《勇者斗恶龙》系列在城镇探索、居民生活、职业培养和指令式回合战斗上的成熟设计方法，但**不复制其他作品的剧情、地图、人物、资产或代码**；不改走需要服务器、联网副本及持续运营的 MMO 路线。

项目已有相当完整的**数据框架、剧情编排、世界/战斗/存档底层代码以及持续增加的场景资源**；当前短板不在“再列更多系统”，而在**实际玩家路径、商业级地图美术、任务输入接线、战斗深度、跨存档事务和全量真实验收**。现阶段执行顺序是：

**M0 / M0.1 核心可靠性 → Batch 1 共用世界交互 → Batch 2 第一幕六章黄金样板 → Batch 3 全世界内容复制与精修 → Batch 4 商业验收与发布。**

**重要判断**：有72章正典或40张地图蓝图，不能等同于72章/40张地图已完成可玩的商业成品。**整体商业完成百分比：暂不提供**，原因是没有覆盖全部内容、当前 SHA、人工操作与目标设备的统一验收分母。

### 1.2 世界与叙事骨架

八大地区：**白砂海岸、三誓诸国、赤炉联邦、海歌群岛、镜眠王国、失落旧洲、天轨圣域、群灯之城**。剧情主题包括灯火与记忆、记录与遗忘、权力与个人选择。各地区必须有独立的视觉语汇、建筑语言、生态、居民生活方式、音乐/音效主题与支线反馈。

玩家标准闭环为：

新游戏和序章 → 在晨露村自由移动 → NPC真实面对面交谈 → 建筑门口进入/离开 → 查找物件与剧情线索 → 地图/道路自然通达 → 野外遭遇或剧情Boss → 正常胜利/失败/撤退处理 → 奖励结算与职业成长 → 补给、商店、旅馆/锻造 → 安全保存、退出与重载 → 下一章事件/任务/场景准确恢复。任何环节只能用正常玩家输入完成，**不得通过后台预设已胜利、传送绕过路线或灌入任务旗标作为商业验收**。

## 5. 分阶段开发路线与验收标准

### M0 → M0.1：工程安全与统一回归（当前最高优先）

**完成门槛**：记录被冻结的`main` SHA、Godot 4.7.2导入/解析、全局smoke、V1/V2/V3损坏恢复、无作弊Boss、40图路线、一次性奖励与故障注入结果；P0=0。未满足即 **M1 HOLD**。

### Batch 1：全世界交互总线与可恢复角色控制

**目标**：所有场景遵守同一套`interact → validate → apply → save → receipt/rollback`合同。统一门口、NPC面对、调查点、对话中移动锁、战斗前后控制、白天/夜晚切换、商店/旅馆/锻造/营地的输入与恢复。

**交付**：稳定的对象ID/距离检查、共享输入事件、统一玩家方向与遮挡、进入/退出/切换场景后恢复；D签收A/B/C公共接口后，出具一套正常玩家可重复操作的验收路线。

**门槛**：新游戏、手动存档、读档、NPC对话、房屋进出、线索互动、随机战斗与回城恢复均有同SHA的实际引擎成功证据。

### Batch 2：第一幕第1–6章商业黄金样板

**目标**：晨露村与白砂港地区打磨成**可发布水平的单机JRPG垂直切片**。优先制作场景骨架→地形/道路/建筑→居民/关键物件→剧情与Boss→视听/光照→可操作引导→实机精修。

**必交**：六章独立内容和路线、村/港/收容所/酒馆/海岸野外/洞窟/浅滩/灯塔所需地图、可见独特NPC生活、可调查家具、Boss演出与公平难度、休息补给、装备职业、存档恢复。所有地形与画面资产要可复用于其余区域，但不可将不同地图简单换色视为完成。

**门槛**：从“新游戏”不跳章、不断链连续打通第六章；无占位画风、无卡地形、无假任务/假结算；主控/键盘及目标PC机型实测、完整截图/录屏和策划美术QA签名。

### Batch 3：全世界规模化内容生产与整合

**目标**：以黄金样板的技术结构、图集规范和交互框架分地区推进全部40张正式地图，打通72章、66Boss、120支线与20职业的实际玩家路径。阶段按地区/章节打包验收，不因一次脚本批量生成而一次性标记完成。

**每件内容准入记录**：唯一ID、所在地图与触发位置、前置条件、玩家动作、UI/对白反馈、战斗/奖励结果、存档键、回访状态、正式资源、测试证据SHA、负责人。一个阶段未过QA，不向其他40图批量复制其BUG。

### Batch 4：商业完整性、性能与发行

**目标**：72章与A/B/C结局完整实玩；Boss与职业数值、NPC对白、所有正式地图表现、正式美术音效、来源/授权审计；Windows与目标移动设备运行与性能优化；安装包、设置/分辨率/输入、错误恢复、发行材料。

**发行门槛**：P0/P1清零；冻结SHA全库Godot验证成功；关键手工长跑验收；正版资源审阅；设备性能/安全区/电量/内存/崩溃证明；发行包签名、平台规范和版本说明。缺任一项不标为商业版完成。

## 6. 统一进度看板与验收口径

后续进度只采用以下成熟度标记，按**系统×地图/章节/对象**填写：

- **DESIGN**：剧情/ID/地图蓝图/原画方案或数据已入库。
- **WIRED**：真实玩家触发入口、逻辑回执、状态变更与存档字段已接入正式运行链。
- **GODOT_VERIFIED**：针对指定源码SHA的真实Godot解析与可执行流程测试**成功**。
- **PLAYER_ACCEPTED**：正常玩家操作/连续通关、美术音效手工验收和跨场景恢复**成功**。
- **RELEASE_ACCEPTED**：商业发行版满足跨平台性能、来源与授权、版本冻结和全部发行门禁。

其中“**成功**”必须写明验证类型、当前SHA和证据路径；没有执行的项目统一写“**未测试**”。对于确实发现的问题，在开放问题表列为**阻塞/P0/P1**，不得把脚本文件存在或历史CI成功写成当前运行成功。

## 7. 下一周期的执行顺序

1. **D拉取最新main**，核对M0.1当前SHA的Core Validation与全库Smoke回执，先解决真实阻塞；日志不是最新或仅跑静态检查，统一记“未测试”。
2. **B先闭环路由**：按40图最终碰撞查不可达点，修第3–6章地点冲突、白砂港双室内真实按键调查、NPC可达性；提交不覆盖D主控。
3. **A补高章Boss与奖励事务证据**：真实战斗胜负、奖励nonce与职业/装备/经济检查。
4. **C继续正式素材分配与样板美术**：原档/候选/正式运行绑定明细、剧情地图唯一视觉、动作图集与灯光/音频；此阶段不做资源路径破坏性迁移。
5. **A/B/C明确冻结批次并交付SHA**，D统一集成，取得当前批次Godot端到端验收结果；通过后才排Batch1/Batch2下一轮。

## 8. 质量、安全与并行协作红线

- **main-only**；不创建分支或 PR、不强推、不把较旧的脚本快照覆盖并行提交。写入前核对最新SHA和相关文件差异。文档单独提交，不触及资源工作树。
- 资源分配未结束时不得整理/删除/重命名美术目录；完成后V5.1也须先引用审计、文件哈希、正式选择清单与克隆检查，失败即停并回滚。
- 正常剧情和奖励靠真正的玩家路径及保存回执，禁止预注入胜利、跳任务、重复发奖或者绕过位置前置。
- 渲染层可以替换素材，不得擅自改变权威地图碰撞、任务前置、玩家状态与存档。
- 旧档升级采用可恢复策略，任何第一次保存覆盖及损坏恢复都必须具备备份/回滚证据。
- 自动化测试结果严格限定到被测的SHA、范围和平台；CI绿色不等于美术审美/剧情质量/移动端性能或发行验收。
